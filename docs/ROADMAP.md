# 长期目标与版本路线

最终目标：**全代码语言、全平台搜集**。围绕避免 AI 重复实现，统一完成本地发现、跨平台候选检索、固定版本证据读取、复用决策、实际集成和验证。

这是持续扩展目标，不是当前覆盖声明。每一版都必须公开已实现来源、未查询范围、认证需求、失败原因及证据缺口；不能把来源不可用当成没有现成实现。

## v0.1：完整流程（已完成第一版验收）

- 共享 core、CLI、MCP 和 Codex 接入。
- GitHub、npm、PyPI 已知分发名核验。
- planned → applied → verified 记录和固定提交证据。

## v0.2：更多来源（已完成）

- 新增 GitLab.com、crates.io、Maven Central、NuGet.org、RubyGems、Packagist。
- 默认自动模式查询全部已实现来源；按生态或明确来源选择缩小查询计划。
- GitLab 固定提交、嵌套命名空间、文件/目录及行区间读取；跨平台仓库身份去重。
- 新包生态的发布版本元数据证据；Maven 保留固定版本 POM；Packagist 记录发布源码引用。
- 本地搜索不再依赖语言扩展名白名单，按 UTF-8 文本和资源预算判断；扩展根目录依赖指纹。
- 公共结果显示来源能力及未选来源；保留超时、认证失败、限流和证据缺口。

验收分开记录：[离线与接口验证](VALIDATION.md)、[实网观察及历史失败](live-smoke-v2.json)。测试通过不代表全生态召回、远程 CI 或新版本宿主激活已经通过。

## v0.3：有预算的分页与失败保留（本地实现已验证）

- 八个需求搜索来源默认最多两页，可配置一至三页；PyPI 包名和 GitLab 精确 URL 维持单次核验。
- 所有第一页任务完成后才继续后续页，共享总预算，最多四个工作任务并发。
- 后续页失败保留已有候选、错误与失败页码；重复页停止并标记覆盖不完整。
- 公开成功页数、条目数、上游总数（如有）、未读信号和停止原因；分页上限隔离缓存。
- 通过公共核心、CLI 和真实 MCP stdio 验证；联网样本及历史失败见 [live-smoke-v3.json](live-smoke-v3.json)。

这一版完成有限页号/偏移分页，不代表完整召回，也没有新增语言生态或代码平台。游标、备用端点、自动重查和跨语言召回策略仍在后续范围。

## v0.4：语段证据与整体任务对齐（本次实现）

- 在共享核心中使用固定解析器切分 JS/TS 家族的结构语段，保留哈希、父级、调用/控制流/写入与 import 事实。
- 新增 `alignment` 契约、`assess_alignment` / CLI `assess`，要求完整任务/约束映射、上下文引用、架构依赖规则、保留现有方案的比较和集成验证计划。
- 确定性阻止缺项、冲突、无效引用、禁止依赖及规划前过期的本地证据；缺口和宿主语义判断分别公开。
- 更新辅助提示词、复用技能及安装分发。语法切分不是全语义分析；当前不证明全局最优，也未增加语言源。

下一步是更多语言的结构解析、可验证的跨文件符号/调用关系和真实模型行为评测；详见[对齐说明](ALIGNMENT.md)及[验证记录](VALIDATION.md)。

## 后续扩展顺序

1. **可靠性与召回**：游标遍历、官方备用端点、失败来源重查、跨语言查询策略、来源间排序公平性和可复现召回样例集；页号/偏移分页已在 v0.3 实现，当前使用固定离线样例验证第二页候选召回。
2. **更多语言生态**：Go 模块、C/C++（Conan/vcpkg）、Swift、Dart/Flutter、Elixir/Erlang、Haskell、R、Julia、Lua、Clojure、Perl、OCaml 等。逐个区分需求搜索、包名核验与代码取证能力，不用包名猜测冒充生态搜索。
3. **更多代码平台**：Gitee、Codeberg/Forgejo、Bitbucket、SourceHut、GitLab 自托管及其他公开托管服务。核查官方 API、授权与速率约束，再增加受控主机配置和凭据隔离。
4. **更完整的证据**：发布归档与仓库提交对应关系、Maven POM 继承/SCM、NuGet 来源映射、非 GitHub/GitLab 代码读取、多模块依赖指纹和更多文本编码。
5. **更多运行平台与 Agent**：保持共享核心，增加客户端适配。按 Windows/Linux/macOS、Node 版本、真实宿主分别验收。

新增来源必须同时交付共享核心接口、失败与覆盖说明、身份/版本规则、证据读取能力或明确缺口、公共接口测试和独立联网观察。仅添加一个来源名称不算完成接入。
