# 长期目标与版本路线

最终目标：**全代码语言、全平台搜集**。围绕避免 AI 重复实现，统一完成本地发现、跨平台候选检索、固定版本证据读取、复用决策、实际集成和验证。

这是持续扩展目标，不是当前覆盖声明。每一版都必须公开已实现来源、未查询范围、认证需求、失败原因及证据缺口；不能把来源不可用当成没有现成实现。

## v0.1：完整流程（已完成第一版验收）

- 共享 core、CLI、MCP 和 Codex 接入。
- GitHub、npm、PyPI 已知分发名核验。
- planned → applied → verified 记录和固定提交证据。

## v0.2：更多来源（已完成）

- 新增 GitLab.com、crates.io、Maven Central、NuGet.org、RubyGems、Packagist。
- 默认自动模式查询全部已实现来源；按生态或明确来源选择缩小查询计划。
- GitLab 固定提交、嵌套命名空间、文件/目录及行区间读取；跨平台仓库身份去重。
- 新包生态的发布版本元数据证据；Maven 保留固定版本 POM；Packagist 记录发布源码引用。
- 本地搜索不再依赖语言扩展名白名单，按 UTF-8 文本和资源预算判断；扩展根目录依赖指纹。
- 公共结果显示来源能力及未选来源；保留超时、认证失败、限流和证据缺口。

验收分开记录：[离线与接口验证](VALIDATION.md)、[实网观察及历史失败](live-smoke-v2.json)。测试通过不代表全生态召回、远程 CI 或新版本宿主激活已经通过。

## v0.3：有预算的分页与失败保留（本地实现已验证）

- 八个需求搜索来源默认最多两页，可配置一至三页；PyPI 包名和 GitLab 精确 URL 维持单次核验。
- 所有第一页任务完成后才继续后续页，共享总预算，最多四个工作任务并发。
- 后续页失败保留已有候选、错误与失败页码；重复页停止并标记覆盖不完整。
- 公开成功页数、条目数、上游总数（如有）、未读信号和停止原因；分页上限隔离缓存。
- 通过公共核心、CLI 和真实 MCP stdio 验证；联网样本及历史失败见 [live-smoke-v3.json](live-smoke-v3.json)。

这一版完成有限页号/偏移分页，不代表完整召回，也没有新增语言生态或代码平台。游标、备用端点、自动重查和跨语言召回策略仍在后续范围。

## v0.4：语段证据与整体任务对齐（已完成本地验证与发布）

- 在共享核心中使用固定解析器切分 JS/TS 家族的结构语段，保留哈希、父级、调用/控制流/写入与 import 事实。
- 新增 `alignment` 契约、`assess_alignment` / CLI `assess`，要求完整任务/约束映射、上下文引用、架构依赖规则、保留现有方案的比较和集成验证计划。
- 确定性阻止缺项、冲突、无效引用、禁止依赖及规划前过期的本地证据；缺口和宿主语义判断分别公开。
- 更新辅助提示词、复用技能及安装分发。语法切分不是全语义分析；当前不证明全局最优，也未增加语言源。

## v0.5：有界跨文件定义关联（已完成本地实现）

- 复用现有 Babel AST，在同一 inspection 的完整证据内关联相对导入、显式命名/默认重导出和稳定顶层函数的直接调用。
- 记录目标模块/语段及未解决原因；同名遮蔽、写入、动态作用域、歧义、截断、外部包、成员调用和重导出循环不猜测目标。
- 对齐时要求选择已关联的被调用语段和中间模块，提示词返回已读调用方、调用点及缺口；部分关联沿用明确承认规则，unknown/conflict 仍阻止采用。
- 保持原有结构预算，另限 300 个调用点和 10 跳重导出。不自动补读文件，不添加运行依赖或语言检索源。

这是静态定义证据关联，尚非完整词法作用域、项目模块解析或运行时调用图。下一步仍包括更多语言结构解析、精确作用域/项目配置、完整调用方检索和真实模型行为评测；详见[对齐说明](ALIGNMENT.md)及[验证记录](VALIDATION.md)。

## v0.6：Python、Go、Rust 结构证据（已完成本地实现）

- 固定 WASM runtime 和三种官方语法资产，增加函数、类型、父级、导入及有界调用/控制/写入事实；保留原始哈希、UTF-16 偏移和行号。
- 共享原有 inspection 预算，语法错误、截断、资源限制保留文本或已读事实及缺口；不执行候选代码，不要求本机语言工具链或运行时下载。
- 新语言不套用 JS/TS 模块解析；导入 unsupported、调用 unresolved。现有 Babel 语段和跨文件定义关联保留，核心/CLI/MCP 统一提供证据和对齐门槛。
- 增加公共核心、CLI、真实 MCP stdio 验证及固定制品/许可归属；没有新增包生态检索来源。此轮是三种语言的结构证据，不是全语言、全语义解析。

## v0.7：更多结构语言与包生态（本次本地实现）

- Java、C#、C、C++ 官方固定 WASM 结构语段、父链、import/include 和语法事实，保留错误/截断/预处理/头文件歧义及原有共享预算。
- Hex 接入官方包名/描述搜索、分页和固定 release 元数据；pub.dev 接入官方 top 名称表匹配与固定版本取证。pub 没有官方承诺的全文需求搜索，本轮不使用未文档接口。
- 共享核心、CLI/MCP 增加 dart/flutter/elixir/erlang 路由，公开源能力、8 小时 pub 语料缓存、发布源码对应未核实和包归档未读取范围。
- 公共接口离线测试与新增来源实网观察分别记录，原始语法资产许可/提交/哈希随包保存。

v0.7 的结构语言后续在 v0.8 扩展如下。包生态继续补充下列范围，pub 的更完整发现能力仍受官方接口限制。

## v0.8：常见语言结构覆盖（本次本地实现）

- 优先增加 PHP、Ruby、Kotlin、Swift，再补 Bash 和 Lua，沿用共享 runtime/预算、父链/UTF-16 哈希及保守错误降级；六份固定上游 release 资产及完整许可随包保存。
- 补充 namespace use、import、require/include/source 与语法调用/写入/控制事实；模块和调用目标仍未解析，动态加载原文及缺口公开。
- 核心、CLI 和真实 MCP stdio 接口验证，统一分析和改编门槛的代码文件识别；包检索来源数量未增加。

后续结构语言优先补 Dart、Scala、SQL、PowerShell 等，再扩展 R、Julia、Haskell 等；Dart 的已检查上游没有 release WASM，本轮继续文本证据，不用其他包的未核实二进制代替。十三种 WASM 语言仍需项目配置和定义关联。

## v1.0：多 Agent 接入（本地实现）

- CLI 的 `init`、`doctor`、`uninstall` 增加 Claude Code、OpenCode 和官方 DeepSeek Harness，默认继续为 Codex。
- 原生 MCP 配置、独立技能目录和项目指令；DeepSeek 使用显式 Cordis overlay，不改动全局 profile。OpenCode JSONC 当前手动配置，自动安装保留原文件。
- 按客户端记录文件归属，保留无关配置和用户修改；发现、取证、对齐和决策继续共享核心。
- 新客户端暂不提供自动补丁守卫。公共 CLI/SDK stdio 测试与真实宿主激活分开报告，详见[接入指南](CLIENTS.md)和[验证记录](VALIDATION.md)。

## v1.1：OpenCode JSONC 自动接入（本地实现）

- `init`、`doctor`、`uninstall` 支持唯一已有的根目录 `opencode.json` 或 `opencode.jsonc`，两种文件均接受注释和尾随逗号；无配置时继续创建 `opencode.json`。
- 使用固定 JSONC 解析依赖，保留无关值与周边注释；托管条目相等时保持配置文本不变。编辑边界空白可能变化，替换托管值时其内部注释可能移除。
- 两个配置同时存在、重复解码键、无效语法、归属记录路径不一致或同名非托管条目均在写入前报告；保留旧版 receipt、其他客户端及共享核心行为。
- 配置文件检查、离线公共 CLI/MCP 验证与实际宿主加载继续分开记录，见[验证记录](VALIDATION.md)。本轮不增加客户端自动补丁守卫。

后续接入工作包括三种新客户端的原生自动触发/守卫，以及各宿主的实际会话验收。

## 后续扩展顺序

1. **可靠性与召回**：游标遍历、官方备用端点、失败来源重查、跨语言查询策略、来源间排序公平性和可复现召回样例集；页号/偏移分页已在 v0.3 实现，当前使用固定离线样例验证第二页候选召回。
2. **更多语言生态**：Go 模块、C/C++（Conan/vcpkg）、Swift、Haskell、R、Julia、Lua、Clojure、Perl、OCaml 等，并继续改进 Dart/Flutter 和 Elixir/Erlang 的代码取证。逐个区分需求搜索、包名核验与代码取证能力，不用包名猜测冒充生态搜索。
3. **更多代码平台**：Gitee、Codeberg/Forgejo、Bitbucket、SourceHut、GitLab 自托管及其他公开托管服务。核查官方 API、授权与速率约束，再增加受控主机配置和凭据隔离。
4. **更完整的证据**：发布归档与仓库提交对应关系、Maven POM 继承/SCM、NuGet 来源映射、非 GitHub/GitLab 代码读取、多模块依赖指纹和更多文本编码。
5. **更多运行平台与 Agent**：保持共享核心，增加客户端适配。按 Windows/Linux/macOS、Node 版本、真实宿主分别验收。

新增来源必须同时交付共享核心接口、失败与覆盖说明、身份/版本规则、证据读取能力或明确缺口、公共接口测试和独立联网观察。仅添加一个来源名称不算完成接入。
